- Give `sypy login` a meaning it can keep: the key it stores belongs to the watcher. A background process cannot be handed a key any other way — neither launchd nor systemd inherits the shell that installed the service — which is what `login` is for. It does not follow that every command run by hand should quietly spend it, and **the surprise there is expensive**: an `ingest` typed at a prompt looks free until the bill. So the stored key is read only by the process that declared itself the spender, which is the watcher and nothing else. With a watcher running, `sypy ingest` asks it to do the filing, so the command still works and spends the right key in the process that owns the write lock; without one it refuses and says so. `OPENAI_API_KEY` is untouched by all of this and still works everywhere: setting it for one command is a deliberate act with a key chosen for that run, which is the opposite case. Be exact about what this guarantees: a hand-typed `ingest` still causes spending when a watcher is running, because the watcher does the filing on its key and prints what it filed — what cannot happen is a command reading the stored key and spending it itself, unattributed. Routing an ingest therefore requires `--input`, since `ingest` otherwise files the current directory, which is a local mistake with a key in your shell and a spend on the service's key without one. **Only `login`, `logout`, and the watcher read the keychain**, not even to write a better error message — reading it is what makes a locked keyring put a password dialog in front of whoever is sitting there, and the first version of this did exactly that and hung for three minutes. `sypy doctor` now asks the watcher whether it has a key rather than looking itself, for the same reason and because it is the only process that knows: a watcher running without one is a failure, where no watcher running is a warning, since the stored key is not knowable from a client by design.
- Let the other commands work while a pass is running, by having the watcher answer for the library it already owns. It serves a Unix socket while it watches — not a new process, since it already holds the write connection and `watchlock` already guarantees one watcher per library, which is what makes "the watcher for this library" a well-defined thing to address. **Reads deliberately do not go through it.** Several read-only connections coexist, so `find`, `list`, `categories`, `sql`, `cited`, and `read` open the database directly and answer whether or not anything is serving — an agent asking what you have filed never depends on a background process being up, which routing reads through the watcher would have quietly broken. The one case that excludes readers is a pass holding the write lock, and that is exactly when the watcher can answer, so the fallback costs a round trip instead of the thirty-second wait it replaces. Changes go the other way: with a watcher running it makes them, and without one the command takes the lock itself exactly as before. What crosses the socket is a whitelist derived from what the commands actually call, so a method added later is not reachable until someone decides it should be, and neither proxy is a way around the read-only open. Nothing starts a watcher on your behalf: a read command that silently launched a background process which spends money is the opposite of the point. The socket lives in the runtime directory rather than beside the rest of the state, because a socket path is capped near 104 bytes and a library a few folders deep would otherwise fail at `bind` with nothing but "path too long" to go on. Ops are serialized on the watcher: each connection is its own task and an ingest awaits the model, so without that a routed pass and the watcher's own overlap — both work out what is new long before either writes, and both file the same document, leaving two store folders for one row. The frame limit is raised on both directions of the socket, since asyncio caps a line at 64 KiB and a `list` of about ninety papers already exceeds it. A library nobody has written yet, and one whose schema predates this build, are handed back to the read-write path rather than failing: read-only cannot create a database and cannot run migration DDL.
- Add `sypy doctor`, which checks the watcher and the model in one command. The question it answers is "why has nothing been filed", and until now that took four commands and knowing which four. Every check is one line saying `ok`, `warn`, or `FAIL`, anything that failed is repeated at the end as the command that fixes it, and it exits non-zero so a script can gate on it. **A service that is installed while nothing is running is a failure, not a warning** — that is the case worth catching, because the folder looks watched and a week goes by; a watcher run by hand is a legitimate way to use this, so merely stopped is a warning. It checks the key by listing models rather than by noting that a key exists: an expired key looks exactly like a working one until the first document, and the call that proves otherwise is free, so `doctor` never costs money — `--offline` skips it anyway. A missing `pdftoppm` is a warning, since only documents with no text layer need it and everything else still works.
- Keep the API key in the system keychain, and put it there with `sypy login`. The key had two homes and both leak in their own way: a `.env` at the repository root is plaintext next to the code, and a key exported in a shell profile reaches the command by hand and **nothing at all** under a supervisor, because neither launchd nor systemd inherits the shell that installed the service — a watcher configured that way starts cleanly and then fails on the first document. macOS Keychain and the Linux Secret Service both unlock at login, so the key is encrypted at rest and a service started at boot can still read it. `sypy logout` forgets it, and says so if an exported key is still set and about to take over. The keychain wins over the environment: otherwise `login` would appear to do nothing on a machine whose profile still exports last year's key. A machine with no keychain — a container, a headless box with no Secret Service — falls through to the environment rather than refusing to start, since that is the ordinary case for the variable and not an error. Logging out survives a backend that allows a write but refuses a delete: a locked Secret Service collection beside an unlocked one is the routine case on Linux, so a refused delete overwrites the entry with nothing, which every later read treats as no key.
- Let the library be asked which of its bibliographies cite a document. `bib add` records the citation in the manuscript that made it, which answers "what does this thesis cite" and leaves "where have I already used this paper" needing every `bib.toml` opened by hand. `sypy cited <id>` now names each bibliography and the key it uses, every `find --json` and `list --json` record carries the same under `cited_by`, and `sypy remove` lists what cites a document before asking to confirm — a citation survives the document being deleted and keeps working, since it is a claim about a paper rather than about a file you hold, but it stops leading anywhere, and that is worth knowing while the choice is still open. **Nothing is stored to answer any of it.** A source already names the `file_id` it cites, so the answer is the records read backwards rather than a second copy of them: a stored index would be a third thing to keep in step with the record and the generated `.bib`, and would be wrong for exactly as long as it took someone to notice — where this cannot disagree with the record because it is the record, and a `bib.toml` edited by hand is answered correctly the moment it is saved rather than after a rebuild nobody remembered to run. A page of records reads the bibliographies once rather than once per row, for the same reason attributes are already fetched for a whole page: `list --json` describes the entire library. A source with no `file_id` — a book cited by hand, something not in this library at all — cites no document here and appears nowhere in the answer.
- Let `sypy ingest --input` name one PDF, and refuse a path that is neither a folder nor a PDF. Filing a single document meant first putting it in a folder of its own, because `--input` was globbed and a folder was the only thing that answered — so filing one paper out of a Downloads folder meant filing the Downloads folder. `discover_pdfs` now takes a file as the list of one it is, which is the whole change: filing one document and filing the folder it sits in are the same request at different scope, and neither needed its own pipeline. The default library moves with it, to `sorted` beside the named file rather than inside it, since `paper.pdf/sorted` is not a folder anything could be written to. The second half is the papercut that made the first hard to find: pointing `--input` at a file, or at a path with a typo in it, printed "filed 0 document(s)" and exited 0 — which reads as "nothing new here" rather than "that is not a folder". The scan itself still answers an unusable path with an empty list, deliberately and now with the reason written down: it runs on every pass of a long-lived watcher, and a watched folder deleted out from under one must not take the service down over an ordinary event. So the check goes where the typo is made instead, in the command, next to the option it is about — a `.txt` file is told it is a `.txt` file and that naming the folder would file what is in it, a path that is not there is told that, and both exit 2 as a usage error rather than 0 as a successful no-op. `watch` is unchanged: it wants a folder, and has always said so loudly.
- Add `sypy read <id>`, which prints a filed document's text. Until now the library could tell you everything about a document except what it said: `find` returned the path to a PDF and left opening it to you, and the only text the tool held was the one-line collapse ingest sends to the model — first pages only, whitespace squeezed out, shaped for something that pays by the character rather than for anyone reading it. `read` is the other reading, and `extract.py` now holds both and says why there are two: `read_document` keeps the lines the page has, because guessing which of them were the document's and which the column's is how a paragraph gets mangled. Text goes to stdout and nothing else does, so `sypy read kahn | grep -i method` and `$(sypy read kahn)` both work; which pages were read, out of how many, goes to stderr, because a reader handed pages 1 to 5 of 300 should not have to work that out — the same split `find` uses for a capped search, and for the same reason. `--pages` takes `3`, `4-9`, or `10-`, which is how you read a book without reading a book; a range running past the end is clipped rather than refused, since naming a page past it is a reasonable way to mean "the rest", while a *first* page past the end is an error, because an empty answer would read as a document with nothing in it. A bad range is refused at the CLI where it arrives, naming the option, rather than surfacing from inside pypdf three layers down. Nothing is sent anywhere and nothing is spent: this is `pypdf` on a local file. A scan has no text layer and this does not OCR it — but where ingest has already paid to have its pages read, that reading is banked in `model_answers` and is printed instead, with stderr saying plainly that it is a model's reading of a picture and not the document's own words, and declining to claim a page range for it, since the banked text is one answer covering several pages and there is no page 3 of it to quote. A scan nobody has read says so, and says that `ingest` is what reads one and that it costs a request. The agent skill gains a section on all of it, including to check the length before reading a long one; it also loses a claim that was already wrong — that `model_answers.page_text` holds the extracted text of every document, when it only ever held scans, and that re-parsing a PDF was the expensive alternative to querying it, when reading a local file costs nothing at all.
- Put the bibliography where the manuscript is, and give it somewhere to think. `sypy bib init "PhD Thesis" --link` and `sypy bib add ... --link` leave a link to the bibliography's whole folder in the directory the command ran in, so a paper is written against `\addbibresource{thesis/references.bib}` and reaches the record, the notes, and the books cited through one name without knowing where the library lives. The link is absolute where the tree's are relative, and for the opposite reason: the tree moves as one piece with the library, while a manuscript directory and a library are independent trees that move for unrelated reasons, so a relative link is the one that breaks when either does. Linking twice is the wanted state rather than an error, and anything already sitting under that name is left exactly as it is — deciding someone else's file is stale is not this tool's call. A cited **book** is now linked into the bibliography as well as written into it, under a folder named for its author and year: a paper is read once and cited, where a book you go back to and read a chapter at a time, so it is the one worth having at hand, and putting it inside the bibliography is what makes the single `--link` carry it to the manuscript too. A second book by the same author in the same year adds its title — `knuth_1984_concrete-mathematics` — and a third matching on that as well is refused rather than filed, because at that point nothing in the record tells the two apart and one folder would quietly hold both; a book with no author goes under its citation key, which is unique within a bibliography and so cannot collide at all. The link points at the document's folder in the store exactly as the tree's links do, so a book reached this way opens the same as a book reached through a category. **Bibliographies now take notes**: `sypy bib note --lib thesis` writes about the manuscript — an outline, an argument, what still has to be cited — and `sypy bib note --lib thesis --cite vaswani` writes about one thing it cites, at `notes/<key>.md`, named by the citation key with a second note spelled `notes/<key>-<name>.md` because they share a folder and an `outline.md` in there would say nothing about whose outline it is. That is deliberately not `sypy note <id>`: the document's own notes describe the document and are shared by every bibliography citing it, where these are what the document does for *this* manuscript, and a paper dropped from one chapter should not take another chapter's reasoning with it. `--cite` accepts a citation key as well as a document and tries the key first and exactly, so notes can still be opened on a source whose document has since left the library. What may be called a note — any markdown or JSON file, a bare word meaning markdown, anything else refused rather than renamed — moves out of `library.py` into `notes.py` and is now read by both, since a rule written twice is a rule that drifts; `sypy note` keeps its behaviour and its errors exactly. `sypy backup` copies `bibs/` with `symlinks=True`, as the store already did: a shelved book is a link into the store, and following it would have copied every book a second time and restored as real files what were links.
- Give the library somewhere to put what you cite. `sypy bib init "PhD Thesis"` starts a bibliography at `bibs/phd-thesis/` inside the library, and `sypy bib add --lib thesis --cite <id>` cites one of the library's own documents in it — one bibliography per manuscript, each keeping its own citation keys, so a key disambiguated in one does not move under another's feet. Either half may be left off and is asked for, with the bibliographies listed and the first offered as the default: a library with one takes a keystroke, a library with several cannot have the wrong one picked for it, and the document is named the way every other command names one, so `--cite vaswani` resolves through the same search and the same `fzf` picker as `note` and `retag`. A bibliography answers to its slug or to its id, because the slug is what a person reads and the id is what survives the folder being renamed. Each holds two files, and **the TOML is the source of truth while the `.bib` is a projection of it**, exactly as the database is the truth behind the store's filenames — which is what makes the `.bib` safe to overwrite on every write, and why a field the library never knew is added by editing `bib.toml` and running `sypy bib build` rather than by editing the file the next `bib add` throws away. The generated file says so in its own header, for whoever finds it first. Every key in a `[[source]]` table except `key`, `type`, `file_id`, and `added_at_ms` is a BibTeX field carried through as written, so the record holds fields this tool has never heard of and a source that is not in the library at all — a book you cite but do not have — is added by hand and rendered like any other. Title, authors, and year come from the library's columns and everything else from the document's attributes, which is what `sypy attr` has been for: only keys that name a BibTeX field cross over, so a verdict or a reading date kept on the same document stays out of the bibliography, and the entry type follows what is there — a `journal` makes it an `@article`, a `booktitle` an `@inproceedings`, nothing at all leaves it `@misc`, since a document filed by this tool is not assumed to be a paper. Keys are spelled `vaswani2017attention`, the spelling nearly every reference manager produces and so the one you guess at when typing `\cite{`; two papers by one author in one year get a trailing letter, the way BibTeX itself answers a collision, and a document with neither an author nor a title is cited by its id rather than as `2017`, for the same reason its link is not called that. TeX's special characters are escaped into the `.bib` and left alone in the record, and titles are double-braced so a style cannot lowercase a title its authors already capitalized. `sypy backup` now copies `bibs/` with the store and the database: a bibliography is hand-made and derivable from nothing, so leaving it out would have made the backup command the thing that lost it. `tomli-w` is a new dependency, for writing the record — `tomllib` only reads, and a hand-rolled quoter is the wrong place to find out that a title contained a backslash.
- Let the person re-tagging say what the model is missing, instead of only saying no. `sypy retag <id>` offered accept, regenerate, or cancel, so the only thing a refusal carried was the path it turned down — and a document the model keeps reading as clinical when it is mathematical takes as many requests to walk away from that reading as you are willing to pay for, because nothing in the loop could tell it. `s` now asks for a sentence — "it is about the maths, not the clinic", "file it near the tax papers" — and the next round is asked under it. It is placed last in the prompt and marked as outranking everything above it, the rejected list included: the person has read the document and the model has read its first pages, and a steer that walks back a path turned down two rounds ago is exactly the correction that rule would otherwise forbid. The latest sentence replaces the one before it rather than accumulating, since someone correcting their own steer means the newer one and two contradictory instructions in a prompt are worth less than either alone. What was asked for is printed beside the answer it produced, so a suggestion that ignored it is visibly that. An empty answer is not a decision: the menu comes back and no request is spent.

- Let a note be called whatever its owner calls it. A note was `notes.md` and only `notes.md`, so a second one about the same document — a reading log, a table pulled out of it, anything a program wanted to write back and read again — had nowhere to go that the library would admit existed.
